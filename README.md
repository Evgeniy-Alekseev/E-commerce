# Продукты и категории

Проект реализует систему учета продуктов и категорий с расширенной объектно-ориентированной архитектурой.

## Функциональность

### Абстрактные классы:
- `BaseProduct` - Абстрактный базовый класс для всех продуктов, определяющий общую интерфейсную функциональность
- `AbstractEntity` - Абстрактный класс для сущностей с общими свойствами (имя, описание)

### Миксины:
- `CreatableMixin` - Миксин, который при создании объекта печатает информацию о классе и параметрах создания

### Класс `Product` (наследуется от `CreatableMixin` и `BaseProduct`):
**Атрибуты:**
- `name` - Название продукта
- `description` - Описание продукта
- `price` - Цена продукта (с геттером и сеттером)
- `quantity` - Количество на складе

**Методы:**
- `__init__` - Инициализация продукта
- `__str__` - Строковое представление продукта в формате `"Название, Цена руб. Остаток: Количество шт."`
- `__add__` - Сложение продуктов одного типа по формуле `(цена * количество) + (цена * количество)`. Сложение продуктов разных типов запрещено.
- `new_product` - Создание нового продукта из словаря данных с проверкой на дубликаты
- `price` (property) - Геттер для получения цены
- `price` (setter) - Сеттер для установки цены с валидацией:
  - Проверка на нулевые и отрицательные значения
  - Подтверждение при снижении цены
  - Автоматический выбор максимальной цены при объединении дубликатов

### Класс `Category` (наследуется от `AbstractEntity`):
**Атрибуты:**
- `name` - Название категории
- `description` - Описание категории
- `__products` - Приватный список продуктов в категории

**Атрибуты класса:**
- `category_count` - общее количество категорий
- `product_count` - общее количество продуктов

**Методы:**
- `__init__` - Инициализация категории
- `__str__` - Строковое представление категории в формате `"Название, количество продуктов: Общее_количество_товаров шт."`
- `__iter__` - Возвращает итератор для перебора продуктов в категории
- `add_product` - Добавление продукта в категорию с автоматическим обновлением счетчиков. Добавлять можно только объекты класса `Product` и его наследников.
- `middle_price()` - Подсчитывает средний ценник всех товаров в категории. Возвращает 0 если категория пуста.
- `products` (property) - Геттер для получения списка продуктов в форматированном виде (каждый продукт на новой строке)

### Класс `Order` (наследуется от `AbstractEntity`):
**Атрибуты:**
- `product` - Ссылка на купленный товар
- `quantity` - Количество купленного товара
- `total_cost` - Итоговая стоимость заказа
- `name` - Название заказа (унаследовано от AbstractEntity)
- `description` - Описание заказа (унаследовано от AbstractEntity)

**Методы:**
- `__init__` - Инициализация заказа с автоматическим расчетом итоговой стоимости и проверкой количества (вызывает ZeroQuantityError при quantity ≤ 0)

### Класс `CategoryIterator`:
**Методы:**
- `__init__` - Инициализация итератора
- `__iter__` - Возвращает сам объект как итератор
- `__next__` - Возвращает следующий продукт в категории

### Класс `Smartphone` (наследник `Product`):
**Дополнительные атрибуты:**
- `efficiency` - Производительность
- `model` - Модель
- `memory` - Объем встроенной памяти
- `color` - Цвет

### Класс `LawnGrass` (наследник `Product`):
**Дополнительные атрибуты:**
- `country` - Страна-производитель
- `germination_period` - Срок прорастания
- `color` - Цвет

### Пользовательские исключения:
- `ZeroQuantityError` - Исключение, возникающее при попытке добавить товар с нулевым количеством в категорию или заказ

### Функции:
- `load_categories_from_json(file_path: str)` - Загружает категории и продукты из JSON-файла. При загрузке автоматически определяет тип продукта (`Product`, `Smartphone`, `LawnGrass`) на основе наличия специфических полей в данных и создает объекты соответствующих классов.

### Новые возможности и улучшения
#### 1. Обработка исключений
- **Валидация количества:** При создании продукта с quantity ≤ 0 вызывается ValueError с сообщением "Товар с нулевым количеством не может быть добавлен"
- **Пользовательские исключения:** Добавлен класс ZeroQuantityError для обработки событий добавления товаров с нулевым количеством
- **Безопасное вычисление средней цены:** Метод middle_price() возвращает 0 для пустых категорий, обрабатывая деление на ноль

#### 2. Улучшенная обработка ошибок
- **Категории:** Метод add_product() перехватывает ZeroQuantityError и выводит информационные сообщения
- **Заказы:** Конструктор Order перехватывает ZeroQuantityError и выводит информационные сообщения
- **Гарантированное завершение:** Все операции добавления товаров используют блок finally для гарантированного вывода сообщения о завершении обработки

#### 3. Безопасные операции
- **Средняя цена:** Безопасное вычисление средней цены товаров в категории с обработкой пустых категорий
- **Добавление товаров:** Контроль типов - можно добавлять только объекты Product и его наследников
- **Валидация данных:** Комплексная проверка входных параметров на всех уровнях системы

### Особенности функциональности
- **Абстрактные классы:** Использование абстрактных классов `BaseProduct` и `AbstractEntity` для определения общего интерфейса
- **Миксины:** Использование миксина `CreatableMixin` для логирования создания объектов
- **Объединение дубликатов:** При создании продукта с уже существующим названием происходит автоматическое объединение:
  - Количество складывается
  - Выбирается максимальная цена из двух
- **Валидация данных:** Система предотвращает установку некорректных значений цены
- **Интерактивное подтверждение:** При снижении цены система запрашивает подтверждение пользователя
- **Типизированное сложение:** Продукты можно складывать только с продуктами того же типа (и его подтипов). Попытка сложить, например, `Smartphone` и `LawnGrass` приведет к ошибке `TypeError`.
- **Типизированное добавление:** В категорию можно добавить только объекты класса `Product` и его наследников (`Smartphone`, `LawnGrass`). Попытка добавить объект другого типа приведет к ошибке `TypeError`.
- **Автоматическое определение типа при загрузке:** Функция `load_categories_from_json` анализирует поля в данных продукта и создает объекты соответствующих классов (`Smartphone`, `LawnGrass` или базовый `Product`).

## Тестирование

Проект включает набор тестов, проверяющих:

### Функциональные тесты:
- Корректность инициализации объектов `Product`, `Category`, `Smartphone`, `LawnGrass`, `Order`
- Работу геттеров и сеттеров цены с различными сценариями
- Создание новых продуктов и объединение дубликатов
- Добавление продуктов в категории
- Подсчет количества продуктов и категорий
- Форматирование списка продуктов
- Сложение продуктов одного типа
- Запрет на сложение продуктов разных типов
- Добавление в категорию только продуктов и его наследников
- Загрузку данных из JSON с автоматическим определением типа
- Работу абстрактных классов и миксинов

### Тесты обработки исключений:
- Валидация количества: Тестирование создания продуктов с нулевым и отрицательным количеством
- Обработка ZeroQuantityError: Тестирование перехвата исключений в методах add_product() и конструкторе Order
- Безопасное вычисление: Тестирование метода middle_price() для пустых категорий
- Вывод сообщений: Проверка корректности информационных сообщений при обработке исключений

### Тесты валидации:
- Обработка отрицательных и нулевых цен
- Подтверждение снижения цены (позитивный и негативный сценарии)
- Работу с пустыми категориями
- Объединение продуктов с разными ценами
- Обработку попыток сложения разных типов продуктов
- Обработку попыток добавления в категорию объектов неверного типа

### Интеграционные тесты:
- Взаимодействие между классами `Product`, `Category`, `Smartphone`, `LawnGrass`, `Order`
- Корректность работы счетчиков при различных операциях
- Обработку граничных случаев
- Работу функции `load_categories_from_json` с различными типами продуктов
- Работу абстрактных классов и миксинов в составе системы

### Покрытие тестами
- **Общее покрытие:** Более 90%
- **Покрытие критической бизнес-логики:** 100%
- **Покрытие обработки исключений:** 100%
- **Тесты включают:** Модульные тесты, интеграционные тесты, тесты граничных случаев, тесты обработки исключений
